# Adaptive representation synthesis and program abstraction

ACCE development stage 3 addresses bounded representational flexibility (CF-03) and program abstraction (CF-05). This is not arbitrary representation invention or unrestricted abstract reasoning.

## Computational model

The evaluator supplies an ordered finite domain of 4, 8, or 16 distinct integer labels (bounded to absolute value 1,000,000). IX-Zero constructs ordinal encodings from their sorted ranks. For size `n`, candidate encodings map rank `i` to `(m*i+c) mod n`, for every odd multiplier `m` and offset `c`. The second candidate family composes this with reflected binary Gray encoding. All these maps are bijections. Their inverse is computed from the enumerated finite domain. A candidate program is `decode(op(encode(a), encode(b)))`, where `op` is a live, promoted word operator from the existing NAND-and-shift synthesis engine at the matching width. The representation learner is not supplied with the appropriate source operator, encoding family, multiplier, or offset for an episode.

A candidate's entire predicted finite-domain behavior can be computed without target outcomes. Syntactic variants that give the same table are retained for analysis, but active inquiry weights distinct tables equally. Teacher-provided training outcomes eliminate incompatible candidates. The existing original IX interpreter runs the `Composition` policy on the actual episode facts to select inquiry, audit, completion, exhaustion, or revision. Six training observations and three fresh passing audits are required for validated predictions; remaining models must agree on the requested input. Training freezes at the first audit. A failed audit blocks the episode. Source-operator invalidation also disables derived capabilities.

An abstraction is induced from two validated, behavior-resolved episodes with distinct domains and the same underlying word operator. The system selects a deterministic canonical syntax from each set of behaviorally equivalent candidates, then anti-unifies matching fields. Different encoding-family, multiplier, or shift fields become typed holes. The template can constrain future candidate generation on new domains; both parent episodes and their source operators must remain live. Canonical syntactic choice is not proof that the learner recovered the evaluator's actual encoding. Templates can be overly restrictive. `fit_with_abstraction` first fits the template on supplied training observations; if it cannot resolve a model with sufficient evidence, it tries the complete candidate family with the same observations. It returns an unaudited episode. Audit outcomes are never reused to select a replacement representation. There is no automatic post-audit relearning in this module.

A validated representation can be registered as a live `Capability` in the existing ACCE workspace. The recursive language engine can use it through learned dispatch bindings, including as an operand of another cognitive objective. No new lexical rule is needed for the demonstration. `representation_demo` builds a fresh workspace and preserves the previous console and demos. It uses a provided synthetic scene and teacher labels, not open-ended conversation.

## Evaluation protocol

`representation_experiment` learns XOR, AND and OR separately from example outcomes using the existing operator synthesis engine (three-bit width, five-gate search, 24 training and three audit inputs for each operator). Each seed generates distinct irregular negative integer domains with eight labels in the scalar learner's supported range. Two source representation episodes establish an abstraction for ordinal-encoded XOR with shifts zero and one. For each target domain, the evaluator constructs a separate finite function using an independent implementation of the encoding. Inputs are shuffled into a 20-input unlabeled inquiry pool, three reserved audit pairs, and 41 held-out pairs. Full search chooses up to 12 training pairs using IX policy and disagreement; on these campaigns it needs six per matched target. The scalar, template-only and adaptive comparisons receive the identical selected training examples and audit pairs. Thus the transfer comparison controls labels but does not measure independent active inquiry efficiency. The raw baseline cannot consume these disjoint signed labels without an encoding. The scalar baseline uses the original signed scalar learner without modification. Source exposure and hypothesis families differ, so this is not a compute-matched comparison against a general learner.

Each 24-seed campaign has 120 target episodes (five task families per seed). The first campaign uses new irregular label sets; the second also changes the two template-matched shifts to two and seven, neither present in the parent episodes. In both campaigns the complete and adaptive arms each score 4,920/4,920 held-out predictions correctly. The template-only arm scores 1,968/1,968 on the two matching families, and abstains on the other 2,952. Both existing baselines abstain on all 4,920. The complete search evaluates 23,040 candidate programs per campaign; the adaptive arm evaluates 14,784 including rejected template candidates, a 35.83% reduction in candidate enumeration, not a measured end-to-end runtime gain. On the two matching families the template uses 384 candidates versus 9,216 for full search, a 24-fold reduction. On the three other families adaptive fallback increases the candidate count relative to complete search (14,400 vs 13,824). Source learning and abstraction construction costs are excluded from these counts.

The random-mapping control abstains on all 984 reserved inputs in each campaign. Each campaign also deliberately changes one held-out outcome after successful validation in each of 24 further episodes: all 24 initial predictions are incorrect, and all 24 episodes are quarantined after corrective feedback. These are separate tests, not part of the 4,920 primary predictions. The hidden exception is not learned automatically.

## Reproduction

```powershell
py -3 -m ix_zero.representation_experiment --seed 184000 --trials 24 --check --output representation_campaign.json
py -3 -m ix_zero.representation_experiment --seed 185000 --trials 24 --novel --check --output representation_novel_campaign.json
py -3 -m ix_zero.representation_demo --check
py -3 -m unittest discover -s tests -v
```

The results directory contains the campaigns, raw reserved-input predictions, local workflow output and integration transcript. Run `py -3 -m ix_zero.representation_demo` interactively. Example: `rule green cube blue cone` computes -24 for the supplied negative-valued scene; `compare inspect red sphere rule green cube blue cone` returns 1 because -9 exceeds -24. These are synthetic demonstrations, not evidence of free-form language comprehension.

## Limits

Only predefined ordinal/Gray encoding families, finite integer domains, binary operations and already promoted word operators are supported. The new abstraction mechanism is bounded field-wise anti-unification, not unrestricted discovery of arbitrary program structures, new primitive operators or domain semantics. The evaluator supplies the domain and examples. It can learn the wrong model if hidden conditions were not observed. Templates and representation episodes are session-local; persistence and post-audit recovery require further work. No standardized external benchmark was run for this stage. No native Windows or remote GitHub CI execution is claimed. Version remains 0.1.0.
